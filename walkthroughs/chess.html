Design a Chess Game

Medium–Hard Java ~30 min read Code: org.nailyourinterview.lld.chess

Two players, White and Black, take turns on an 8 × 8 board. Each piece type moves in its own way. A move is legal only if it does not leave your own king in check. A player with no legal move is checkmated (if in check) or stalemated (a draw).

The classes are easy. The hard part is move validation: who checks the shape of a move, who checks the path, and who checks the king. This page gives each check one owner.

Every LLD answer follows the same 5 steps. Requirement gathering splits into 3 buckets: extensibility, dynamic input and high traffic. Click a step to jump to it.

    1.2 Core functional requirements

    • Create an 8 × 8 board with the 32 pieces in the start position.
    • Two players, White and Black. White moves first. Turns alternate.
    • A move is given as two squares, for example e2 e4.
    • Each piece moves in its own shape. Rook, bishop, queen and the pawn double step cannot jump. The knight can.
    • A piece cannot capture a piece of its own colour.
    • A move that leaves your own king in check is illegal (this covers pins and walking into check).
    • After each move: if the opponent has no legal move → checkmate (in check) or stalemate (not in check). Otherwise announce check if needed.
    • A pawn that reaches the last row becomes a queen. A player can resign.
    • Keep a list of all moves.

    1.4 Dynamic (user input)

    Nothing about the game is hard-coded except the rules. Main reads the input with a Scanner:

    • The names of the white and black players.
    • Each move, as two squares: e2 e4. Or the word resign.
    Validate every inputA square must be a letter a–h and a digit 1–8. board.getCell("z9") returns null, and Game.validate() turns that into a clear error. A bad move never changes the board, and the same player moves again.

    1.5 High traffic (concurrency)

    Not needed here. One local game, one thread. Say this out loud, so the interviewer knows you checked.

    For an online version: a GameManager holds Map<gameId, Game>. Two clients can send a move at the same time, so makeMove must run under a lock per game (or a single-thread queue per game). Send a move number with each request and reject a stale one. Note: leavesKingInCheck() changes the board for a moment, so it must also run inside the lock.

    1.6 Non-functional requirements

    • Correct — an illegal move never changes the board.
    • Readable — each piece holds its own rule; no giant switch on piece type.
    • Testable — you can put any position on the board and check one rule.
    Interview tipSay the scope out loud: “Standard rules, check / checkmate / stalemate, promotion to queen. Castling and en passant are extensions.” This saves 15 minutes.

    2Core entities + breakdown

    Read the requirements again. Underline the nouns. Most nouns become classes. Verbs become methods.

    A game has two players and a board of 64 cells. A cell may hold a piece: a king, queen, rook, bishop, knight or pawn, in white or black. A player makes a move from one cell to another. The game checks the move, records it and decides the status: active, a win, or stalemate.

    All 6 pieces answer one question: “can I go from here to there?”. So they share one parent: Piece. Each child only describes its own shape of move.

    EntityTypeResponsibility
    GameService / orchestratorHolds the board, 2 players, move list, turn and status. Validates a move, applies it, then checks for check, checkmate and stalemate.
    BoardModelOwns the 8 × 8 Cell grid and the start position. Answers geometry questions: getCell("e2"), isPathClear, isUnderAttack, isInCheck.
    CellModelOne square: row, column and an optional piece. Knows its name ("e2").
    Piece (abstract)ModelColour and type. canMove() runs the shared checks, then calls the child’s isValidMove().
    King, Queen, Rook, Bishop, Knight, PawnModelOne move shape each. Sliding pieces ask the board for a clear path.
    PlayerModelName and colour.
    MoveModelWho moved what, from where, to where, and what was captured. The history is a List<Move>.
    Color, PieceType, GameStatusEnumsWHITE/BLACK; KING…PAWN; ACTIVE, WHITE_WINS, BLACK_WINS, STALEMATE.
    PieceFactoryFactoryCreates a piece from a type and a colour. Used for the start position and for promotion.
    Common mistakeDo not write switch (piece.getType()) inside Game to check moves. Each piece checks its own shape. Game checks only the rules that need the whole board: whose turn it is, and the king’s safety.

    5.2 Piece — the shared rules

    model/pieces/Piece.java
    @Getter
@RequiredArgsConstructor
public abstract class Piece {
    private final Color color;
    private final PieceType type;

    // Rules shared by every piece. Each subclass only adds its own shape of move.
    public boolean canMove(Board board, Cell from, Cell to) {
        if (from == to) {
            return false;
        }
        if (!to.isEmpty() && to.getPiece().getColor() == color) {
            return false;   // cannot capture your own piece
        }
        return isValidMove(board, from, to);
    }

    protected abstract boolean isValidMove(Board board, Cell from, Cell to);

    public abstract char getLetter();

    // White = upper case (K), Black = lower case (k)
    public char getSymbol() {
        return color == Color.WHITE ? getLetter() : Character.toLowerCase(getLetter());
    }
}

    Key idea — Template Method. canMove() is the fixed recipe. Step 3 of the recipe, isValidMove(), is different for each piece. No child can forget the “own piece” check.

    5.3 The six pieces

    Only the shape of the move changes. dRow and dCol are the distances in rows and columns.

    model/pieces/King, Queen, Rook, Bishop, Knight (isValidMove only)
    // King: one step in any direction
return dRow <= 1 && dCol <= 1;

// Rook: straight line, nothing in between
boolean straight = from.getRow() == to.getRow() || from.getCol() == to.getCol();
return straight && board.isPathClear(from, to);

// Bishop: diagonal, nothing in between
return dRow == dCol && board.isPathClear(from, to);

// Queen: rook + bishop
return (dRow == 0 || dCol == 0 || dRow == dCol) && board.isPathClear(from, to);

// Knight: L-shape (1,2) or (2,1). It jumps, so no path check.
return dRow * dCol == 2;
    model/pieces/Pawn.java
    public class Pawn extends Piece {
    public Pawn(Color color) {
        super(color, PieceType.PAWN);
    }

    @Override
    protected boolean isValidMove(Board board, Cell from, Cell to) {
        int dir = getColor() == Color.WHITE ? 1 : -1;        // white moves up, black moves down
        int startRow = getColor() == Color.WHITE ? 1 : 6;
        int dRow = to.getRow() - from.getRow();
        int dCol = Math.abs(to.getCol() - from.getCol());

        // 1 step forward into an empty cell
        if (dCol == 0 && dRow == dir) {
            return to.isEmpty();
        }
        // 2 steps forward from the start row, both cells empty
        if (dCol == 0 && dRow == 2 * dir && from.getRow() == startRow) {
            return to.isEmpty() && board.isPathClear(from, to);
        }
        // 1 step diagonal, only to capture
        return dCol == 1 && dRow == dir && !to.isEmpty();
    }

    @Override
    public char getLetter() {
        return 'P';
    }
}

    The pawn is the only piece whose direction depends on colour, and the only one that moves one way and captures another way. Expect follow-up questions here.

    5.6 Board — grid, path and attack checks

    Row 0 is rank 1 (White’s side). Column 0 is file a. So "e2" → col = 'e' - 'a' = 4, row = '2' - '1' = 1.

    Name → grid index
    col = name.charAt(0) - 'a'
    row = name.charAt(1) - '1'
    Path walk (rook, bishop, queen):
    stepRow = signum(toRow - fromRow)
    stepCol = signum(toCol - fromCol)
    Orange: the cells isPathClear(a1, a5) looks at.
    model/Board.java
    @Getter
public class Board {
    public static final int SIZE = 8;
    private static final PieceType[] BACK_ROW = {ROOK, KNIGHT, BISHOP, QUEEN, KING, BISHOP, KNIGHT, ROOK};

    private final Cell[][] grid = new Cell[SIZE][SIZE];

    public Board() {
        for (int row = 0; row < SIZE; row++) {
            for (int col = 0; col < SIZE; col++) {
                grid[row][col] = new Cell(row, col);
            }
        }
        setupPieces();
    }

    private void setupPieces() {
        for (int col = 0; col < SIZE; col++) {
            grid[0][col].setPiece(PieceFactory.createPiece(BACK_ROW[col], Color.WHITE));
            grid[1][col].setPiece(PieceFactory.createPiece(PAWN, Color.WHITE));
            grid[6][col].setPiece(PieceFactory.createPiece(PAWN, Color.BLACK));
            grid[7][col].setPiece(PieceFactory.createPiece(BACK_ROW[col], Color.BLACK));
        }
    }

    // "e2" -> grid[1][4]. Returns null for bad input.
    public Cell getCell(String name) { ... }

    // Walk one step at a time from 'from' towards 'to'. Every cell in between must be empty.
    public boolean isPathClear(Cell from, Cell to) {
        int stepRow = Integer.signum(to.getRow() - from.getRow());
        int stepCol = Integer.signum(to.getCol() - from.getCol());
        int row = from.getRow() + stepRow;
        int col = from.getCol() + stepCol;

        while (row != to.getRow() || col != to.getCol()) {
            if (!grid[row][col].isEmpty()) {
                return false;
            }
            row += stepRow;
            col += stepCol;
        }
        return true;
    }

    // Can any piece of the 'attacker' colour move to this cell?
    public boolean isUnderAttack(Cell target, Color attacker) {
        for (Cell[] row : grid) {
            for (Cell cell : row) {
                Piece piece = cell.getPiece();
                if (piece != null && piece.getColor() == attacker && piece.canMove(this, cell, target)) {
                    return true;
                }
            }
        }
        return false;
    }

    public boolean isInCheck(Color color) {
        return isUnderAttack(findKing(color), color.opposite());
    }

    public Cell findKing(Color color) { /* scan the grid for this colour's KING */ }
    public void printBoard() { /* rank 8 at the top, '.' for an empty cell */ }
}

    isUnderAttack reuses canMove. “Is my king in check?” is the same question as “can any enemy piece move to my king’s cell?”. One rule, two uses.

    5.7 Game — the orchestrator

    service/Game.java
    @Getter
public class Game {
    private final Board board;
    private final Player[] players;
    private final List<Move> moves;
    private int turn;                 // index into players: 0 = white, 1 = black
    private GameStatus status;

    public Game(Player white, Player black) {
        this.board = new Board();
        this.players = new Player[]{white, black};
        this.moves = new ArrayList<>();
        this.turn = 0;
        this.status = GameStatus.ACTIVE;
    }

    public boolean makeMove(String fromName, String toName) {
        Player player = getCurrentPlayer();
        Cell from = board.getCell(fromName);
        Cell to = board.getCell(toName);

        // 1. validate
        String error = validate(player, from, to);
        if (error != null) {
            System.out.println("Invalid move: " + error);
            return false;
        }

        // 2. apply
        Piece piece = from.getPiece();
        Piece captured = to.getPiece();
        to.setPiece(piece);
        from.setPiece(null);

        Move move = new Move(player, from, to, piece, captured);
        moves.add(move);
        System.out.println(move);
        promoteIfNeeded(to);

        // 3. check the opponent, then pass the turn
        updateStatus(player.getColor().opposite());
        turn = 1 - turn;
        return true;
    }

    private String validate(Player player, Cell from, Cell to) {
        if (status != GameStatus.ACTIVE)            return "game is over";
        if (from == null || to == null)             return "use squares like e2 e4";
        Piece piece = from.getPiece();
        if (piece == null)                          return "no piece on " + from.getName();
        if (piece.getColor() != player.getColor())  return "that is not your piece";
        if (!piece.canMove(board, from, to))        return piece.getType() + " cannot move ...";
        if (leavesKingInCheck(from, to))            return "your king would be in check";
        return null;
    }

    // Try the move, look at the king, then undo it.
    private boolean leavesKingInCheck(Cell from, Cell to) {
        Piece piece = from.getPiece();
        Piece captured = to.getPiece();
        to.setPiece(piece);
        from.setPiece(null);

        boolean inCheck = board.isInCheck(piece.getColor());

        from.setPiece(piece);
        to.setPiece(captured);
        return inCheck;
    }

    private void updateStatus(Color opponent) {
        boolean inCheck = board.isInCheck(opponent);
        boolean canMove = hasAnyLegalMove(opponent);

        if (inCheck && !canMove) {
            status = opponent == Color.WHITE ? GameStatus.BLACK_WINS : GameStatus.WHITE_WINS;
            System.out.println("Checkmate! " + getCurrentPlayer().getName() + " wins.");
        } else if (!canMove) {
            status = GameStatus.STALEMATE;
            System.out.println("Stalemate! It is a draw.");
        } else if (inCheck) {
            System.out.println("Check!");
        }
    }

    // Brute force: every piece of this colour x every cell. 64 x 64 is small.
    private boolean hasAnyLegalMove(Color color) {
        for (Cell[] row : board.getGrid())
            for (Cell from : row) {
                Piece piece = from.getPiece();
                if (piece == null || piece.getColor() != color) continue;
                for (Cell[] targetRow : board.getGrid())
                    for (Cell to : targetRow)
                        if (piece.canMove(board, from, to) && !leavesKingInCheck(from, to)) return true;
            }
        return false;
    }

    // promoteIfNeeded(cell): a pawn on the last row becomes PieceFactory.createPiece(QUEEN, colour)
    // resign(): the current player loses
}

    Try, look, undo. leavesKingInCheck is the one method that handles pins, moving into check and “you must answer a check”. You do not need a separate rule for each case.

    7Design patterns
    
  
    Be honest in the interview. Say which patterns the code uses and which ones you would add.
    
  
    
    
    Template Method used
    Piece.canMove() runs the shared checks, then calls the abstract isValidMove(). Each piece fills in one step.
    
    
    Inheritance + polymorphism used
    Game and Board call piece.canMove(). They never ask which piece it is.
    
    
    Simple Factory used
    PieceFactory.createPiece(type, color) for the start position and for promotion.
    
    
    Composition used
    Game has-a Board, Board has-a Cell grid, Game has-a move list.
    
    
    Command would add
    Move already stores captured. Add execute() / undo() for take-back and replay. The demo board’s ↶ Undo does this.
    
    
    Strategy would add
    MoveChooser for human vs. bot players. BoardSetup for variants such as Chess960.
    
    
    Observer would add
    Fire onMove, onCheck, onGameOver. Console, UI and tests subscribe. Removes System.out from the model.
    
    
    Chain of rules would add
    Turn validate() into a list of MoveRules. Castling and en passant become new rules, not edits.
    
    
    Singleton avoid
    Do not make Game or Board a singleton. You lose parallel games and clean tests.
    
    
    Type switch in Game avoid
    if (type == ROOK) … else if (type == BISHOP) … breaks OCP. Each new piece edits Game.
    
  
    
  
    SOLID check
    
      
      
    • S — Piece: shape of a move. Board: geometry and attacks. Game: turns, king safety, status. (Printing in Board and Game breaks this a little.)
      • 
      
    • O — A new piece (for example a fairy “Archbishop”) is a new subclass + one factory case. Game does not change.
      • 
      
    • L — Any Piece subclass works where a Piece is expected.
      • 
      
    • D — Weak today: Game creates its own Board. Inject it (or a BoardSetup) to test any position.
      • 
    
    
  
    
  
    Example: undo with Command
    

    Game.java (addition)
    public boolean undo() {
    if (moves.isEmpty()) return false;
    Move last = moves.remove(moves.size() - 1);
    last.getFrom().setPiece(last.getPiece());     // the original piece (a pawn, even after promotion)
    last.getTo().setPiece(last.getCaptured());    // null or the captured piece
    turn = 1 - turn;
    status = GameStatus.ACTIVE;
    return true;
}
    
  
    This works only because Move keeps both piece and captured. Store what you need to reverse an action at the moment you do it.
    

    

    



    

    
  
    8Similar problems
    
  
    A problem is similar only if the Chess model carries over: a grid board of cells, two players who alternate, pieces that sit on cells, and a loop that validates a move, applies it and checks for the end. The problems below share that skeleton. They are ranked by how much you can reuse.
    

  
    The shared skeleton
    
    Game → owns Board → owns Cell[][] · each cell may hold a piece · turn = 1 - turn · loop: read move → validate → apply → record → check end → switch turn.
    
  
    

  
    
    
    ProblemReuse from ChessNew part to learn
    
    
      
    Chinese chess (Xiangqi)
    closest    		Everything: Board, Cell, abstract Piece with isValidMove, factory, check / checkmate by try-and-undo.9 × 10 board, a palace that limits the general, the cannon that jumps exactly one piece to capture, the “flying general” rule.
    
      
    Checkers (Draughts)8 × 8 board, two colours, pieces on cells, path checks, promotion (man → king), move history.Captures jump over a piece. Captures are forced. Multi-jump in one turn. A player with no move loses.
    
      
    Othello (Reversi)8 × 8 grid, two colours, the same step-by-step ray walk as isPathClear, the “no legal move” check.A move places a disc and flips lines in 8 directions. No legal move → pass the turn. Winner = most discs.
    
      
    Tic-Tac-ToeGame → Board → Cell grid, 2 players, turn switch, validate → apply → check end.No piece types, no movement — only place a mark. Win = a full row, column or diagonal. Draw when the board is full.
    
      
    Connect FourSame as Tic-Tac-Toe, plus the direction walk (signum steps) for “4 in a row”.A disc drops to the lowest free row of a column. Check 4 directions from the last disc.

    Traps → fixes
    
  
    
    
      
    Move leaves own king in check (pin, walk into check)Try the move, call isInCheck, undo
    
      
    Rook / bishop / queen jump over piecesboard.isPathClear(from, to)
    
      
    Knight path-checkedKnight jumps: dRow * dCol == 2 only
    
      
    Pawn captures straight or moves diagonally to an empty cellForward needs empty; diagonal needs a piece
    
      
    Pawn double step through a pieceStart row + isPathClear + target empty
    
      
    Capture own pieceOne shared check in Piece.canMove
    
      
    Checkmate = “king has no move”No legal move for any piece (block or capture can save)
    
      
    Stalemate counted as a winNo legal move + not in check = draw
    
      
    Wrong player movespiece.getColor() != player.getColor()
