Design a Vending Machine

Medium Java ~25 min read Code: org.nailyourinterview.lld.vending_machine

A vending machine sells snacks from slots. The user inserts coins or notes, picks a product code, and gets the item plus change. The machine must refuse a sold-out item and must not take money it cannot give change for.

This is the classic State pattern question. The same button (“select A1”) does different things when the machine is idle, has money, or is dispensing. The second skill it tests is making change from a limited cash box.

Every LLD answer follows the same 5 steps. Requirement gathering splits into 3 buckets: extensibility, dynamic input and high traffic. Click a step to jump to it.

    1.2 Core functional requirements

    • Slots with a code, a product (name, price) and a quantity.
    • Accept coins and notes. Keep a running balance.
    • Select a product by code. Reject: unknown code, sold out, not enough money, no change possible.
    • On success: drop the item, return the change, start again.
    • Cancel before dispensing: refund the exact money inserted.
    • Maintenance mode: no sales; the operator can restock.

    1.4 Dynamic (user input)

    The layout and the cash are not hard-coded in the machine. They come in at runtime:

    • Slots and products: vm.addSlot(new Slot("A1", new Product("Coke", 25), 5)).
    • Starting cash: vm.loadCash(Denomination.COIN_5, 1).
    • User input: insertMoney(Denomination.NOTE_20) and selectProduct("A1"), in any order and any number of times.
    Validate the inputMoney is a Denomination enum, so the machine cannot receive a ₹3 coin. Prices are int rupees — never double for money. An unknown slot code is rejected. Negative restock counts are not checked today — add a guard.

    1.5 High traffic (concurrency)

    Not needed here. One physical machine serves one user at a time. All calls come from one keypad, one after another. Say this out loud, so the interviewer knows you checked.

    If they ask: a mobile app and the keypad may hit the same machine at once. Make the four public actions synchronized, or push every action into one event queue that a single thread handles. For a fleet, each machine owns its own state; only stock reports go to a server.

    1.6 Non-functional requirements

    • Correct money — never lose or invent a rupee. Refund the exact coins.
    • Readable — no big switch (status) in every method.
    • Extensible — a new state or payment type is a new class.
    Interview tipDraw the state diagram before the class diagram. Once the states and arrows are right, the classes follow.

    2Core entities + breakdown

    Read the requirements again. Underline the nouns. Most nouns become classes. Verbs become methods.

    A vending machine has slots. Each slot holds a product with a price. The user inserts coins and notes, selects a slot code and gets the item and change from the cash box. The machine is idle, has money, is dispensing or is in maintenance.

    The last sentence is the key. “Idle”, “has money” and “dispensing” are states. Each state handles the same 4 actions in its own way. So each state becomes a class.

    EntityTypeResponsibility
    VendingMachineService / contextHolds inventory, cash box, inserted money and the current state. Forwards every user action to the state.
    VendingStateInterfaceinsertMoney, selectProduct, dispense, cancel, getStatus.
    IdleState / HasMoneyState / DispensingState / MaintenanceStateStateOne class per state. Does the work for that state and moves the machine to the next one.
    InventoryModelSlots by code. Add, look up, restock.
    SlotModelCode, product, quantity. isEmpty, decrement, restock.
    ProductModelName and price (int rupees).
    CashBoxModelCount of each denomination. Checks and makes change.
    DenominationEnumCOIN_1 … NOTE_100, each with a value.
    MachineStatusEnumIDLE, HAS_MONEY, DISPENSING, MAINTENANCE — a label for each state.
    Common mistakeDo not write if (status == IDLE) … else if (status == HAS_MONEY) … inside every method of VendingMachine. With 4 states × 4 actions that is 16 branches, and a new state edits all of them. One class per state keeps each branch in one place.

    5.2 Product, Slot, Inventory

    model/Product.java · model/Slot.java · model/Inventory.java
    @Getter
@AllArgsConstructor
public class Product {
    private final String name;
    private final int price;          // whole rupees, never double
}

@Getter
@AllArgsConstructor
public class Slot {
    private final String code;
    private final Product product;
    private int quantity;

    public boolean isEmpty() { return quantity == 0; }

    public void decrement() {
        if (quantity == 0) throw new IllegalStateException("Slot " + code + " is empty");
        quantity--;
    }

    public void restock(int count) { quantity += count; }
}

public class Inventory {
    private final Map<String, Slot> slots = new LinkedHashMap<>();

    public void addSlot(Slot slot) { slots.put(slot.getCode(), slot); }
    public Slot getSlot(String code) { return slots.get(code); }

    public void restock(String code, int count) {
        Slot slot = slots.get(code);
        if (slot == null) { System.out.println("No slot " + code); return; }
        slot.restock(count);
    }
}

    5.3 CashBox — making change

    model/CashBox.java
    public class CashBox {
    private final Map<Denomination, Integer> counts = new EnumMap<>(Denomination.class);

    public CashBox() {
        for (Denomination d : Denomination.values()) counts.put(d, 0);
    }

    public void add(Denomination d, int count) { counts.merge(d, count, Integer::sum); }
    public void addAll(List<Denomination> money) { money.forEach(d -> add(d, 1)); }
    public void removeAll(List<Denomination> money) { money.forEach(d -> add(d, -1)); }

    public boolean canMakeChange(int amount) { return plan(amount) != null; }

    public Map<Denomination, Integer> makeChange(int amount) {
        Map<Denomination, Integer> change = plan(amount);
        if (change == null) throw new IllegalStateException("Cannot make change for " + amount);
        change.forEach((d, n) -> add(d, -n));        // take the coins out of the box
        return change;
    }

    // Greedy: largest denomination first, limited by what is in the box
    private Map<Denomination, Integer> plan(int amount) {
        Map<Denomination, Integer> change = new LinkedHashMap<>();
        Denomination[] all = Denomination.values();
        for (int i = all.length - 1; i >= 0 && amount > 0; i--) {
            Denomination d = all[i];
            int use = Math.min(amount / d.getValue(), counts.get(d));
            if (use > 0) {
                change.put(d, use);
                amount -= use * d.getValue();
            }
        }
        return amount == 0 ? change : null;
    }
}

    Check, then act. canMakeChange and makeChange share one plan(), so the check and the real payout always agree. Limit: greedy with limited coins can miss an answer. ₹6 with one ₹5 and three ₹2 coins: greedy takes ₹5, then needs ₹1 and fails; 2 + 2 + 2 works. Fix with a short backtracking search (see §7).

    5.5 IdleState

    state/IdleState.java
    @AllArgsConstructor
public class IdleState implements VendingState {
    private final VendingMachine machine;

    @Override
    public void insertMoney(Denomination money) {
        machine.addMoney(money);
        System.out.println("Inserted ₹" + money.getValue() + ". Balance: ₹" + machine.getBalance());
        machine.setState(new HasMoneyState(machine));          // IDLE → HAS_MONEY
    }

    @Override public void selectProduct(String code) { System.out.println("Insert money first."); }
    @Override public void dispense() { System.out.println("Insert money and select a product first."); }

}

    5.6 HasMoneyState — the busy one

    state/HasMoneyState.java
    @AllArgsConstructor
public class HasMoneyState implements VendingState {
    private final VendingMachine machine;

    @Override
    public void insertMoney(Denomination money) {
        machine.addMoney(money);                                // stay in HAS_MONEY
        System.out.println("Inserted ₹" + money.getValue() + ". Balance: ₹" + machine.getBalance());
    }

    @Override
    public void selectProduct(String code) {
        Slot slot = machine.getInventory().getSlot(code);
        if (slot == null) { System.out.println("Invalid code " + code + "."); return; }
        if (slot.isEmpty()) {
            System.out.println(slot.getProduct().getName() + " is sold out. Pick another or cancel.");
            return;
        }

        int price = slot.getProduct().getPrice();
        int balance = machine.getBalance();
        if (balance < price) {
            System.out.println(slot.getProduct().getName() + " costs ₹" + price + ". Insert ₹" + (price - balance) + " more.");
            return;
        }

        // The inserted money can be part of the change, so add it to the box before checking
        CashBox cashBox = machine.getCashBox();
        cashBox.addAll(machine.getInsertedMoney());
        if (!cashBox.canMakeChange(balance - price)) {
            cashBox.removeAll(machine.getInsertedMoney());     // undo: refund stays possible
            System.out.println("Cannot return ₹" + (balance - price) + " change. Insert exact amount or cancel.");
            return;
        }

        machine.setSelectedSlot(slot);
        machine.setState(new DispensingState(machine));         // HAS_MONEY → DISPENSING
        machine.dispense();
    }

    @Override public void dispense() { System.out.println("Select a product first."); }

    @Override
    public void cancel() {
        System.out.println("Cancelled. Refund: " + machine.getInsertedMoney());
        machine.resetTransaction();
        machine.setState(new IdleState(machine));               // HAS_MONEY → IDLE
    }

    @Override public MachineStatus getStatus() { return MachineStatus.HAS_MONEY; }
}

    Why add the inserted money first? The user’s own coins can be part of the change for the same sale. Price ₹25; the user inserts ₹10, ₹10, ₹10, ₹2, ₹2 (₹34), so the change is ₹9. The box holds only one ₹5 coin. With the user’s two ₹2 coins added, 5 + 2 + 2 = 9 works. If the check fails, the coins come out again, so cancel still refunds the exact money.

    5.7 DispensingState and MaintenanceState

    state/DispensingState.java · state/MaintenanceState.java
    @AllArgsConstructor
public class DispensingState implements VendingState {
    private final VendingMachine machine;

    @Override
    public void dispense() {
        Slot slot = machine.getSelectedSlot();
        int change = machine.getBalance() - slot.getProduct().getPrice();

        slot.decrement();
        System.out.println("Dispensed " + slot.getProduct().getName() + ".");

        if (change > 0) {
            Map<Denomination, Integer> coins = machine.getCashBox().makeChange(change);
            System.out.println("Change ₹" + change + ": " + coins);
        }

        machine.resetTransaction();
        machine.setState(new IdleState(machine));               // DISPENSING → IDLE
    }

    @Override public void insertMoney(Denomination money) { System.out.println("Dispensing. Please wait."); }
    @Override public void selectProduct(String code) { System.out.println("Dispensing. Please wait."); }
    @Override public void cancel() { System.out.println("Too late to cancel. Dispensing."); }
    @Override public MachineStatus getStatus() { return MachineStatus.DISPENSING; }
}

@AllArgsConstructor
public class MaintenanceState implements VendingState {
    private final VendingMachine machine;

    @Override
    public void insertMoney(Denomination money) {
        System.out.println("Out of service. ₹" + money.getValue() + " returned.");
    }
    @Override public void selectProduct(String code) { System.out.println("Out of service."); }
    @Override public void dispense() { System.out.println("Out of service."); }
    @Override public void cancel() { System.out.println("Out of service."); }
    @Override public MachineStatus getStatus() { return MachineStatus.MAINTENANCE; }
}

    5.8 VendingMachine — the context

    service/VendingMachine.java
    @Getter
public class VendingMachine {
    private final String id;
    private final Inventory inventory = new Inventory();
    private final CashBox cashBox = new CashBox();
    private final List<Denomination> insertedMoney = new ArrayList<>();
    @Setter private VendingState state;
    @Setter private Slot selectedSlot;

    public VendingMachine(String id) {
        this.id = id;
        this.state = new IdleState(this);
    }

    // user actions: the current state decides what happens
    public void insertMoney(Denomination money) { state.insertMoney(money); }
    public void selectProduct(String code)      { state.selectProduct(code); }
    public void dispense()                      { state.dispense(); }
    public void cancel()                        { state.cancel(); }

    // operator actions
    public void startMaintenance() {
        if (state.getStatus() != MachineStatus.IDLE) {
            System.out.println("Finish the current transaction first.");
            return;
        }
        System.out.println("Maintenance started.");
        state = new MaintenanceState(this);
    }

    public void endMaintenance() {
        if (state.getStatus() != MachineStatus.MAINTENANCE) return;
        System.out.println("Maintenance finished.");
        state = new IdleState(this);
    }

    public void restock(String code, int count) {
        if (state.getStatus() != MachineStatus.MAINTENANCE) {
            System.out.println("Restock only in maintenance mode.");
            return;
        }
        inventory.restock(code, count);
        System.out.println("Restocked " + code + " +" + count + ".");
    }

    public void addSlot(Slot slot) { inventory.addSlot(slot); }
    public void loadCash(Denomination d, int count) { cashBox.add(d, count); }

    // helpers used by the states
    public void addMoney(Denomination money) { insertedMoney.add(money); }
    public int getBalance() { return insertedMoney.stream().mapToInt(Denomination::getValue).sum(); }
    public void resetTransaction() { insertedMoney.clear(); selectedSlot = null; }
    public MachineStatus getStatus() { return state.getStatus(); }
}

    The four user methods are one line each. That is the sign the State pattern is working. The machine keeps the list of inserted coins, not just a number, so a refund returns the same coins.

    7Design patterns
    
  
    Be honest in the interview. Say which patterns the code uses and which ones you would add.
    
  
    
    
    State used
    VendingState + 4 classes. The machine forwards each action to state. Each state picks the next state with machine.setState(...).
    
    
    Context object used
    VendingMachine holds the shared data (inventory, cash box, inserted money) that all states read and change.
    
    
    Enum with data used
    Denomination(value): a fixed set of valid money, each with its value. No magic numbers.
    
    
    Composition used
    Machine has-a Inventory and a CashBox. Each part does one job and can be tested alone.
    
    
    Strategy would add
    ChangeStrategy (greedy / backtracking) inside CashBox; PaymentStrategy for cash, card, UPI.
    
    
    Observer would add
    Low stock or low coins → notify the operator. Removes System.out from the model.
    
    
    Factory / cached states would add
    One instance of each state per machine, handed out by a small factory, instead of new on every transition.
    
    
    Big switch on status avoid
    switch (status) in every method. 4 states × 4 actions = 16 branches spread over the class.
    
  
    
  
    SOLID check
    
      
      
    • S — States handle flow, CashBox handles coins, Inventory handles stock.
      • 
      
    • O — A new state is a new class. But a new action (e.g. refund) touches the interface and all 4 states — the known cost of State.
      • 
      
    • L — Any VendingState can be the current state.
      • 
      
    • I — Each state must implement all 4 actions, even ones it rejects. A default method that prints “not allowed” would cut the noise.
      • 
      
    • D — States depend on the concrete VendingMachine. Fine at this size.
      • 
    
    
  
    
  
    Example: change making that never misses (backtracking)
    

    CashBox.plan() — backtracking version
    private Map<Denomination, Integer> plan(int amount) {
    return search(amount, Denomination.values().length - 1);
}

// Try the largest coin first; if the rest cannot be paid, use one fewer and retry
private Map<Denomination, Integer> search(int amount, int i) {
    if (amount == 0) return new LinkedHashMap<>();
    if (i < 0) return null;
    Denomination d = Denomination.values()[i];
    for (int use = Math.min(amount / d.getValue(), counts.get(d)); use >= 0; use--) {
        Map<Denomination, Integer> rest = search(amount - use * d.getValue(), i - 1);
        if (rest != null) {
            if (use > 0) rest.put(d, use);
            return rest;
        }
    }
    return null;
}
    
  
    Same signature, so canMakeChange and makeChange do not change. ₹6 from {₹5, ₹2, ₹2, ₹2}: try one ₹5 → ₹1 left, fails → try zero ₹5 → 2 + 2 + 2. Only 7 denominations, so the search is tiny.

    // VendingMachine: every action is one line
public void selectProduct(String code) { state.selectProduct(code); }

// HasMoneyState.selectProduct: 4 checks, then move on
if (slot == null || slot.isEmpty() || balance < price) return;   // with a message each
cashBox.addAll(inserted);
if (!cashBox.canMakeChange(balance - price)) { cashBox.removeAll(inserted); return; }
machine.setState(new DispensingState(machine));
machine.dispense();

// DispensingState.dispense
slot.decrement(); cashBox.makeChange(balance - price);
machine.resetTransaction(); machine.setState(new IdleState(machine));
